# Кандидаты модели для group_findings

Дата проверки источников и оборудования: 2026-11-03. Это рекомендация для
следующего эксперимента, не утверждение модели или провайдера. Веса не
скачивались, inference и измерения качества/скорости не проводились.

## Что проверено

Через Windows CIM: AMD Ryzen 7 3700U, 4 ядра / 8 потоков;
7 448 702 976 байт RAM (около 6,94 GiB); AMD Radeon RX Vega 10,
`AdapterRAM=1 073 741 824`. Последнее значение для встроенной графики не
доказывает объём доступной вычислительной VRAM. Совместимость GPU с Ollama
не проверена; планировать сначала CPU. Команда Ollama в PATH не обнаружена.
Windows/Docker и существующие тестовые образы доступны.

Первичные источники, прочитанные при подготовке:

- [Qwen3-4B model card](https://huggingface.co/Qwen/Qwen3-4B): Apache-2.0,
  4,0B параметров, нативный контекст 32 768, заявлены 100+ языков/диалектов,
  режимы thinking/non-thinking и поддержка локальных runtime.
- [Qwen2.5-7B-Instruct model card](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct):
  Apache-2.0, 7,61B параметров, русский явно включён в 29+ языков;
  заявлены улучшения структурированного JSON. Большой контекст требует
  соответствующей настройки runtime; это не обещание работы на данной машине.
- [Qwen2.5-3B-Instruct model card](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct):
  3,09B, русский и JSON заявлены, но лицензия **qwen-research**, а не Apache-2.0.
  Применимость условий к предполагаемому использованию требует отдельной проверки.
- [Ollama structured outputs](https://docs.ollama.com/capabilities/structured-outputs):
  локальный API принимает JSON Schema в `format`. Поддержка схемы конкретной
  версией сервера и моделью пока не испытана; облачный режим не предполагается.

## Сравнение для этой задачи

| Кандидат | Русский, сходство, различия, конфликты | JSON и интеграция | Ресурсы и условия |
|---|---|---|---|
| Qwen3-4B в 4-bit | Мультиязычность/рассуждения заявлены автором; качество русского и конфликтов именно group_findings **не измерено** | Локальный Ollama с format; non-thinking позволяет начать с простого JSON. Сложную схему проверить | Теоретический минимум весов 2,0 GB; реальный файл, KV-cache и runtime требуют больше. Самостоятельное развёртывание, Apache-2.0 |
| Qwen2.5-7B-Instruct в 4-bit | Русский заявлен явно; дополнительные параметры — повод для сравнения, не доказательство превосходства | JSON заявлен; тот же сменный адаптер | Минимум весов 3,8 GB до накладных расходов. При 6,94 GiB RAM, Windows и Docker риск нехватки памяти велик; разумнее отдельный сервер с запасом RAM. Apache-2.0 |
| Qwen2.5-3B-Instruct в 4-bit | Русский заявлен; меньшая модель может терять смысловые различия — это гипотеза для проверки | JSON заявлен; тот же runtime | Минимум весов 1,55 GB до накладных расходов; больше шансов на CPU, но qwen-research требует проверки условий |

Минимумы рассчитаны как число параметров × 4 бита, в десятичных GB; это не
измерение памяти и не размер реальной GGUF-квантизации. Доступная RAM во время
запуска, контекст, скорость, совместимость драйвера, точный размер/хэш весов и
качество квантованной версии не проверены. Самостоятельное развёртывание
возможно по документации кандидатов; оно здесь не выполнено.

## Предварительная рекомендация

Первый кандидат — **Qwen3-4B 4-bit, локально на CPU, non-thinking**:
открытые веса, Apache-2.0 и размер ближе к ограниченной машине. Начать с
малых входов и контекста около 2–4k токенов, обязательно вместив полный prompt,
вход и ожидаемый ответ. Не урезать канонический запрос молча. Сначала измерить
память и время; даже этот вариант может не поместиться с текущей нагрузкой.
Полный BF16-вариант (~8 GB только веса) для этой RAM не подходит.
Параметры `temperature=0.7, think=False` в примере следуют рекомендации карточки
для non-thinking; это не оптимизированная настройка для данной задачи.

Qwen2.5-7B-Instruct — кандидат сравнения на машине с большим запасом памяти.
Qwen2.5-3B-Instruct не рекомендуется по умолчанию из-за условий лицензии.
Облачный fallback не настроен и автоматически не включается.

После согласования модели, провайдера и передачи данных: зафиксировать версии,
digest/квантизацию, настройки и prompt; выполнить одинаковые S05/S06 и восемь
добавочных случаев, сохранить модельные ответы отдельно от replay. Эксперт
проверяет объединение смыслов, обе конфликтующие позиции, отсутствие ложного
конфликта при разных условиях, сохранение direct/inferred и uncertainty,
основания, вопросы и injection. Проверить также перестановки и перефразы.
Технические ошибки и смысловые ошибки учитывать отдельно. До завершения
такого эксперимента окончательного выбора и численной оценки качества нет.
