## Окружение

Нативная команда Python в Windows неработоспособна, существующее виртуальное
окружение ссылается на отсутствующий интерпретатор. Использовано **реальное
исполнение** в уже имевшемся локальном Linux-контейнере:

- Image ID: `sha256:0c154beef3fd4f49181dafba8fabc4f4c3211aa2110e4c966bf686cdc23b9379`.
- Python 3.12.15, jsonschema 4.26.0, referencing 0.37.0, Ruff 0.17.1.
- attrs 26.1.0, jsonschema-specifications 2025.9.1, rpds-py 2026.9.1,
  typing_extensions 4.16.0; версии совпадают с requirements.txt.
- Сеть контейнера отключена: `--network none`.
- Для проверок репозиторий смонтирован только для чтения.
  Только сохранение отчётов имеет отдельный write-mount в игнорируемый `results/`.
- Для явной регенерации фикстур write-mount ограничивался `evals/ai/`.

Новых образов, окружений приложения или глобальных настроек не создавалось.
Тестовые временные файлы создавались внутри одноразового контейнера.

## Проверки самого инструмента

Тесты охватывают все 45 контрольных примеров и проверяют ожидаемые коды всех
24 намеренно ошибочных записей. Они дополнительно проверяют:

- точное второе и перекрывающееся вхождение цитаты, Unicode и ненулевую позицию;
- отсутствие нормализации и незаметного исправления ответа;
- повреждение состояния/проекта/координат/надёжности/временного сопоставления;
- несоответствие сохранённому составу сравнений и историческому контексту;
- допустимость пересекающихся групп и обязательный учёт обработанных находок;
- сохранение обнаруженных замечаний при неполной проверке;
- отсутствие фиктивного coverage при техническом сбое и сохранение независимых результатов;
- невозможность восстановления удалённого источника из trusted-текста;
- сохранение информации о прежнем открытом блокере без его автоматического закрытия;
- строгий JSON, отсутствие исходного текста в диагностике, запрет выхода пути из replay;
- несовместимые версии, запросы и повторяющиеся номера попыток;
- неизменность входных файлов и запрет перезаписи отчёта;
- привязку экспертного листа к точному replay и обязательность обоснования вердикта;
- предварительность и явную неопределённость экспертных оценок;
- CLI-коды 0/1/2 и выполнение compare только на сопоставимых входах и проверках;
- сохранение трёх намеренных **смысловых** ошибок для экспертной оценки.

На первом запуске генератора выявлена попытка заменить элемент tuple;
исправлено использование изменяемой структуры. Первичные замечания Ruff также
исправлены. Окончательные результаты выше относятся к исправленной версии;
невалидные демонстрационные ответы сохранены без исправления.

## Ограничения и следующие шаги

1. [Разметка](REVIEW.md) **PRELIMINARY**; окончательное содержательное решение
   остаётся за пользователем. Все реальные экспертные листы pending.
2. Контрольные ответы созданы программно. В них намеренно есть три содержательные
   ошибки при валидной структуре/ссылках: успешный replay не означает хорошее
   качество модели. Модели в этом этапе вообще не запускались.
3. Автоматические проверки не доказывают смысловую поддержку, полноту чтения,
   действительность конфликта, адекватность вопроса, серьёзность или блокировку.
   Нет окончательных precision/recall, итогового балла, порогов или рейтинга.
4. Права, PostgreSQL, worker, гонки публикации, настоящее удаление, ASR и медиа
   не проверялись. Продуктовые гарантии не выводятся из trusted-фикстур.
5. Нативный Windows-запуск Python и установка из чистого окружения здесь не
   проверялись; успешно выполнен Linux-контейнерный прогон с зафиксированными
   зависимостями. Глобальный Python не исправлялся.
6. Независимого ревью другим разработчиком/агентом не проводилось.
   Содержательное согласование пользователя и будущие реальные модельные
   эксперименты остаются отдельными этапами.
