# Ф1б — текстовые материалы в интерфейсе

Основание: явное разрешение пользователя во вложенной задаче от 2026-10-21,
DEC-008/009 и действующий API И2а. Исходная ветка main, HEAD `a4cd0e4`, дерево
чистое. Ф1а завершена и повторно не реализуется.

Разрешены только frontend текстовых отзывов/документов, типы/ошибки общего
ApiClient, применимые проверки и адресные документы. Backend endpoints,
миграции, модель данных и защита Origin/CSRF остаются действующими.

Подход: раздел Материалы внутри проверенного проекта; отдельные списки,
курсоры и формы; hash-маршруты раздела и выбранного материала. После POST
успех показывается только по ответу API; созданный материал открывается по
его ID независимо от страницы UUID. Текст отправляется без преобразований,
отображается через текстовые узлы с сохранением пробелов/переводов строк.
Ошибки доступа снимают весь проектный интерфейс до ручной повторной проверки;
остальные ошибки одного списка не скрывают второй. AbortController и ключ
проекта ограничивают время жизни запросов/данных. Черновики — только в памяти.

Шаги:

1. Изучить API/правила/код и зафиксировать ограниченное разрешение.
2. Реализовать навигацию, списки, формы, чтение и ошибки.
3. Проверить TypeScript/build и браузерные сценарии на настоящих API/PostgreSQL
   через Vite proxy и собранный интерфейс; сохранить регрессии Ф1а.
4. Просмотреть desktop/mobile формы/списки/длинный текст, обновить README/TESTING
   и записать фактические результаты и ограничения.

Workflow `.github/workflows/i1.yml` проверяет backend/AI-контракты/restart;
frontend build и Playwright в него не входят. CI backend не доказывает Ф1б.
Commit/push/merge/публикация и платные вызовы не разрешены.
И2б и остальные продуктовые функции в этот запуск не входят.

## Результат

Ф1б завершена в разрешённых границах DEC-010. В проекте доступны Обзор и
Материалы; раздел и выбранный материал восстанавливаются из hash после reload.
Отзывы и документы имеют независимые формы/списки/курcоры/ошибки и читаются
по ID. Созданный материал открывается даже при недоступной первой странице
списка. У документа показывается название из API, у отзыва — тип и технический
ID; сведения об авторах, датах и общем количестве не выдумываются.

Счётчик использует Unicode code points. Проверка blank не изменяет отправляемые
title/text; ограничения окончательно проверяет сервер. Полный сохранённый текст
показывается через текстовый узел с white-space: pre-wrap, переносом длинных
слов и табуляцией. Формы сохраняют ввод при ошибке; после потери ответа POST
нет автоматического повтора, есть явное неопределённое состояние и обновление
списка перед повтором. Успех появляется только по успешному ответу API.

При переоценке сессии проект скрыт, затем заново проверяется его доступ.
Подтверждённая та же учётная запись/проект сохраняет открытый черновик после
ошибки. 401, смена пользователя, отзыв доступа или смена проекта не возвращают
прежние материалы; состояние ограничено ключом пользователя/проекта и жизнью
запросов. Список проектов также обновляется после переоценки сессии.
Новых endpoints/миграций/модели данных/обработки не вводилось.

## Первоначальные ошибки и исправления

Первый прогон: 11 passed / 6 failed. Подпись вложенного textarea переставала
находиться точным label-селектором после ввода; введена явная связь for/id.
Уточнены два тестовых ожидания без изменения контрактов: отдельный статус
успеха при одновременной загрузке и reload для сброса уже раскрытой пагинации
при проверке материала вне первой страницы. Один worker Windows завершился
с кодом 3221226505; причина не подтверждена, в итоговых прогонах не повторилось.

Следующий прогон: первые 6 сценариев прошли, затем Vite перестал отвечать,
остальные 11 завершились ошибками соединения. В коде Vite найден обработчик
закрытия stdin, завершающий сервер вне режима CI. Для webServer Vite задан
`CI=true` как режим неинтерактивного процесса; обычный npm run dev не изменён.
После этой настройки полный прогон 17/17 и последующие итоговые 18/18 прошли.
Связь конкретного завершения с событием stdin отдельно не трассировалась.
Это локальная настройка теста, а не результат GitHub CI. Предупреждение
NO_COLOR/FORCE_COLOR окружения Playwright сохраняется и не подавляется.
