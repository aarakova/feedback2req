Статус: завершённый аудит и предложения, 2026-10-23–24. Не является утверждением новых API,
физической схемы или реализации И2б. Основание — текущий запрос пользователя
«Задача: подготовка backend к единой рабочей области проекта и следующему этапу обработки».

- Выполнить применимые backend-проверки на собственной изолированной PostgreSQL.
- Проверить статус/согласованность И2б и подготовить ограниченное предложение
  следующей итерации; очередь, m02b и исполняющий worker без отдельного согласия
  не создавать. Не менять AI-контракты или evals/ai.
- Дополнить этот файл результатами, зависимостями и вопросами согласования.

## 3. Этап A: матрица поддержки рабочей области

Префикс `v=/api/v1`, `p=v/projects/{project_id}`. Member включает Owner и участника
с can_approve=true. Раздел интерфейса не является основанием для нового endpoint.

| Экран / действие | Существующий endpoint | Полномочия | Готовность | Ограничения |
|---|---|---|---|---|
| Список проектов / создание | GET/POST v/projects | Сессия; POST + Origin/CSRF | Реализовано, проверено | Страницы items/next_cursor; чужие проекты не перечисляются |
| Открытие проекта / шапка | GET p | Member | Реализовано, проверено | Возвращает name/permissions, без counters и статусов обработки |
| Настройки / переименование | PATCH p, {name} | Owner + Origin/CSRF | Реализовано, проверено; AUD-01 исправлен | Нет версии/If-Match; последовательные записи не предотвращают последнюю перезапись имени |
| Определение роли | GET p и Project.permissions | Member | Реализовано | Owner не хранится отзывной строкой; Approver не администратор |
| Доступ / список | GET p/access | Owner | Backend реализован; UI в отдельной ветке | UUID и флаги, без login/email; owner включён; страницы не единый snapshot |
| Добавить/изменить участника | PUT p/access/{user_id}, {can_approve} | Owner + Origin/CSRF | Реализовано, проверено | Upsert; нет conditional-create/версии; нужен UUID зарегистрированного User |
| Удалить участника | DELETE p/access/{user_id} | Owner + Origin/CSRF | Реализовано, проверено | 204 и при отсутствии строки; Owner неизменяем; передача владения отсутствует |
| Материалы / списки | GET p/sources, GET p/documents | Member | Реализовано, проверено | Раздельные страницы; полный текст в items, нет total/search/media |
| Материалы / карточка | GET p/sources/{id}, GET p/documents/{id} | Member | Реализовано, проверено | Только текущее сохранённое состояние, без истории/редактирования |
| Материалы / добавление | POST p/sources, POST p/documents | Member + Origin/CSRF | Реализовано, проверено | Только text; сохранение не запускает обработку; POST не идемпотентен |
| Обзор / заголовок и реальные материалы | GET p и существующие material lists | Member | Частично | Можно показать доступные записи/число загруженных; точного summary нет |
| Обзор / семантические показатели | Нет | Не назначаются новым контрактом | Не реализовано | Показывать недоступность функции, не фиктивные 0 |
| Находки / группы | Нет | Будущие правила Member | Не реализовано | Прототип — демо, не источник данных |
| Требования / решения | Нет | Будущие Member/Approver по домену | Не реализовано | Нет физических таблиц и HTTP-контрактов |
| Обработка / start/get/retry | Нет; три операции только в I2B_SPEC | Предложенный Member | Требует утверждения/реализации И2б | Не обращаться к несуществующим маршрутам ради навигации |
| Восстановление/завершение сессии | GET/DELETE v/auth/session | Сессия; DELETE + Origin/CSRF | Реализовано, проверено | 401 после expiry/revoke/logout; cookie HttpOnly |

Сериализация имен/прав/доступа и сохранения материалов использует короткий
Project FOR UPDATE; доступ читается после получения блокировки. Сессия тоже
блокируется, время expiry проверяется после ожидания. Составные FK связывают
state с собственными материалом и проектом. Тексты сохраняются без нормализации.
Чтение в момент начала запроса не обещает отзыв уже переданных браузеру данных:
frontend должен отменять/игнорировать поздние ответы после утраты контекста.

## 4. Передача frontend: реальные формы и ошибки

Источник: [routes](../../backend/feedback2req/api/routes.py),
[schemas](../../backend/feedback2req/api/schemas.py),
[materials](../../backend/feedback2req/api/materials.py),
[project service](../../backend/feedback2req/projects/service.py).

```typescript
type User = { id: string; login: string };
type Session = { user: User; csrf_token: string };
type Project = {
  id: string; owner_id: string; name: string; execution_mode: string;
  permissions: { is_owner: boolean; is_member: boolean; can_approve: boolean };
};
type Access = {
  user_id: string; is_owner: boolean; is_member: boolean; can_approve: boolean;
};
type TextSource = { id: string; state_id: string; kind: 'text'; text: string };
type ProductDocument = { id: string; state_id: string; title: string; text: string };
type Page<T> = { items: T[]; next_cursor: string | null };
type ApiFailure = {
  error: { code: string; message: string; details: {}; request_id: string };
};
```

Это описание действующих JSON-ответов, не добавление нового публичного DTO.
POST sources: `{kind:"text",text}`; POST documents: `{title,text}`; PATCH project:
`{name}`; PUT access: `{can_approve:boolean}`. Неизвестные поля запрещены,
can_approve требует настоящий boolean. Сортировка страниц — UUID по возрастанию,
размер страницы серверный (обычно 50). Успешный POST material — 201, project PATCH
и access PUT — 200, access DELETE — 204 без JSON body.

| HTTP / code | Что обязан различать frontend |
|---|---|
| 401 unauthenticated | Нет действующей сессии: убрать приватные данные, восстановить вход |
| 401 invalid_credentials | Одинаковая ошибка неизвестного пользователя и неверного пароля |
| 403 forbidden | Не хватает Owner-права; это не доказательство потери Member-доступа ко всему проекту |
| 403 csrf_rejected / origin_rejected | Ошибка проверки запроса; не автоматически повторять запись и не выдавать за отзыв членства |
| 404 not_found | Недоступный/несуществующий проект или материал не различаются; при ошибке материала можно отдельно перепроверить GET p |
| 404 http_error | В частности, несуществующий маршрут; вызов будущего /runs не доказывает утрату проекта |
| 409 owner_access_immutable | Нельзя изменить/удалить Owner через access |
| 409 login_unavailable | Login регистрации занят |
| 422 invalid_request | Структура/UUID/неизвестные поля/невалидные значения, включая исправленные случаи AUD-01 |
| 422 invalid_user / invalid_login / invalid_text / json_required | Неизвестный User для назначения; неверный login; недопустимый текст; JSON обязателен для anonymous auth |
| 413 body_too_large / text_too_large | Независимые пределы body=16384 bytes и текста=8192 code points по умолчанию; текст не обрезается |
| 429 rate_limited | Лимит register/login, не общий запрет работы с проектом |
| 500 internal_error / сетевой сбой | Безопасное сообщение; исход изменяющего запроса может быть неопределённым |

Все ответы no-store и X-Request-ID; ошибка содержит тот же request_id. Для
изменений нужны неизменённый Origin браузера, cookie и текущий X-CSRF-Token.
Пароли/CSRF не сохраняются в localStorage. У материалов/проектов нет действующего
Idempotency-Key контракта: автоматический повтор POST может создать дубль.
После неопределённого PUT/DELETE access читается текущее состояние без утверждения,
что этим доказан исторический исход команды. Отсутствие участника на одной странице
не доказывает его отсутствия; PUT остаётся upsert, как зафиксировано DEC-012.

Не добавлять role switcher прототипа. Не подставлять числа/fixtures в отсутствующие
разделы. Не трактовать execution_mode=mock как выполненную обработку. AUD-03 из QA
(HTML maxlength считает UTF-16, backend — code points) передаётся frontend-агенту;
файлы его интерфейса этим аудитом не исправляются.

Без новых API можно показывать реально загруженные материалы и «Загружено N».
Полный обход страниц даёт число наблюдённых записей при неизменном наборе, но
не единый snapshot при конкурентном добавлении: новый случайный UUID может
оказаться до уже пройденного cursor. Для dashboard это нельзя называть точным
«Всего на текущий момент». API lists передаёт полные тексты, поэтому обход ради
одного counter также избыточен. Нет идентификации/подсчёта независимых участников.

### Ограниченное предложение overview API — НЕ РЕАЛИЗОВАНО

Новая навигация не требует endpoint. Если нужен точный материал-счётчик в обзоре,
предлагается отдельно согласовать `GET p/overview`, Member, сессия/no-store,
без запуска обработки. Предлагаемый первый ответ:

```json
{
  "project_id": "<uuid>",
  "calculated_at": "<UTC RFC3339>",
  "material_counts": {"text_sources": 2, "product_documents": 1},
  "semantic_metrics": {"availability": "not_implemented"}
}
```

Числа в примере иллюстративны: реализация обязана считать их в БД. Настоящий
пустой поддержанный набор даёт 0; неподдержанная семантическая подсистема не
получает фиктивных counters. Сетевой/SQL-сбой — ошибка, не not_implemented и не 0.
Read должен давать согласованный снимок доступа/двух счётчиков, без текстов и
учёта сессий/states как материалов; неизвестный/недоступный project — одинаковая 404.

Критерии будущих проверок: пустой/непустой проект; оба вида материалов; несколько
states одного header не увеличивают count; чужие refs/отзыв членства; согласованный
snapshot при конкурентном добавлении; no-store/без текста; отсутствие запуска
run; отсутствие нулей для ещё не реализованных метрик. Физическое создание новых
states допустимо в тесте, не означает добавления API редактирования.
Контракт не добавлен в API.md/код. Полная семантическая аналитика проектируется
после появления данных; перечень её полей этим примером не утверждается.

### Ближайшая обоснованная backend-итерация — предложение

После отдельного утверждения указанного снимка и разрешения реализации брать
только И2б: (1) m02b/репозитории/ограничения, (2) три HTTP-команды и read model,
(3) реальный inspect_text и один worker/recovery/watchdog, (4) изолированные
PG/fault/restart-проверки и минимальная интеграция Compose/CI. Существующие
volume, данные, cookie/Origin/CSRF и права сохраняются. UI запуска обработки,
overview endpoint и AI не включать автоматически.

Сначала должны пройти schema/протокольные/HTTP проверки, затем реальный путь
сохранённый текст → explicit start → записанные числа, с restart и двумя независимыми
units. Ошибка одной части не должна превращать весь run в completed. Приёмка
watchdog требует реального выхода/restart, а не одного unhealthy. Любой обход
условий утверждённой спецификации требует остановки соответствующей части работ
и согласования изменения. Сейчас m02b/очередь/worker не создаются.
