# Формальная проверка ожиданий: автономная версия 1

Основание: поручение пользователя от 2026-11-04. База после `git fetch origin`:
`integration/ai-foundation`, `410b936e451629a53ca1eb0fb15a4908961155b6`.
Собственная ветка `feat/formal-expectation-checks`; чужие worktree не изменяются.

## Границы

- Только автономный детерминированный модуль `ai/formal_expectations/` с Z3,
  JSON-интерфейсом, CLI и синтетическими тестами. Три продуктовые AI-роли,
  AI-контракты 1.0, backend F2, worker и generate_requirements сохраняются.
- Учитываются BR-005, FR-012, AC-04, AI-инварианты и границы §7.2
  AI_CONTRACTS.md. Оценочный контур изучается как образец воспроизводимости;
  его предварительная смысловая разметка не становится формальным эталоном.
- Статья «Правило классификации пар пользовательских ожиданий при неполных
  сведениях» отсутствует среди доступных вложений/файлов. Реализуются формулы
  из задания, без заявления полного воспроизведения опубликованного метода.
- Локальная модель: один явно сопоставленный объект/параметр; конечная
  перечисленная область ситуаций; независимое от ситуации множество значений
  (bool, enum или замкнутый рациональный интервал с единицей измерения).
- Неизвестное C/A обозначается null. Ω — явно перечисленный конечный полный
  набор вариантов заполнения неизвестных полей; известные поля фиксированы.
  Проверяются область и согласованность каждого варианта. Полнота относительно
  реального мира не выводится из перечисления: это обязанность поставщика модели.
  Необъявленная полнота, пустое Ω и техническое прерывание различаются.

только утверждения принятой ограниченной модели. Не утверждаются глобальная
совместимость совокупности, истинность извлечения LLM и качество реальных AI.
