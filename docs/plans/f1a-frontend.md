# Ф1а — вход и проекты

Основание: запрос пользователя от 2026-10-21 с явным разрешением Ф1а;
DEC-006/007/008 и действующий API. Исходное дерево чистое, HEAD `746c0f4`.

Объём: React/TypeScript/Vite в `frontend/`, регистрация, вход/выход,
восстановление сессии, список/создание/открытие проектов и полномочия из API.
Визуальный референс — тёмный вариант `observer` из `prototype/index.html`.
Материалы, участники, обработка и остальные экраны в этот этап не входят.

Технический подход внутри утверждённого стека: относительный `/api/v1`,
cookie с `credentials: same-origin`, CSRF только в памяти. Vite на
`http://localhost:5173` сохраняет Origin при proxy в API; backend получает
ровно этот `F2R_ALLOWED_ORIGIN`. В собранном приложении API раздаёт статику
с того же origin. Навигация через hash сохраняет адрес проекта при reload
без серверного SPA fallback. Ответы защищённых запросов после ухода со
страницы игнорируются; 401 удаляет клиентское состояние сессии.

## Результат

Ф1а реализована в разрешённых границах (DEC-009). Регистрация не выполняет
автоматического входа. Вход/восстановление берут сессию и CSRF из API,
пользователь создаёт/открывает проект и продолжает работу после reload.
Пагинация использует next_cursor. Полномочия Owner/Member/Approver приходят
с сервера, не вычисляются из локальной роли. При возвращении во вкладку
сессия и проектные данные запрашиваются заново. 401 очищает защищённый UI;
при выходе защищённые экраны размонтируются до ответа сервера. Неуспешный
выход показывается как ошибка с повтором; поздний ответ не возвращает данные.
Пароль и session token не записываются в браузерные хранилища.

Сборку раздаёт FastAPI через `/` и `/assets`; маршруты API и их защита сохранены.
Dockerfile собирает React в отдельной стадии Node 24. README содержит команды
разработки с Vite proxy и запуска собранного интерфейса. Рабочая БД не менялась;
использовалась только PostgreSQL из compose.test.yaml и отдельные тестовые схемы.
