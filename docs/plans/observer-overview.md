## Результаты

Все строки исходной матрицы реализованы. Переходы используют hash-query
`requirements?filter=...`; выбранная карточка может сохранять этот фильтр.
Неизвестные/дублирующиеся/посторонние параметры отвергаются как неизвестный
маршрут. Фильтр и выбор переживают reload, при смене фильтра старый локальный
выбор не мешает новой выборке. Новые HTTP-запросы не добавлены.

KPI/легенда/категории оснований — ссылки только для подтверждённых чисел,
включая 0. Остальные значения — статичные элементы с объяснением, без href.
Числа должны быть неотрицательными безопасными целыми; NaN/Infinity/дроби не
превращаются в статистику. Обычный App по-прежнему передаёт unavailable.

Группы получили полосы по явному groupScaleMaximum и openIssues, внимание —
независимые сведения о решении/основаниях/блокерах/замечаниях/проверке.
Пустой partial-массив не означает отсутствие открытых случаев. Статус empty
подтверждает отсутствие записей выборки, но не изобретает глобальные нули;
пустой проект с подтверждёнными агрегатами проверяется отдельным zero fixture.

## Минимальные backend-зависимости и ограничения

1. Авторитетные агрегаты проекта: 4 KPI, 3 категории решений и 3 категории
   оснований Approved с явным охватом/неизвестностью. Не total из material pages.
2. Группы: стабильный ID, название, отдельные counts находок/требований/открытых
   замечаний связанных требований, подтверждённый масштаб. Если максимума нет,
   полоса неизвестна; открытые замечания не считаются по неполному issue-списку.
3. Внимание: ID/название, HumanDecision, доступность оснований, явное наличие
   блокеров и число открытых замечаний, состояние проверки/охват.
4. Согласованные данные чтения требований/групп для целевых экранов и область
   применения фильтров/пагинации. Клиентские ссылки не утверждают HTTP-контракт.

Новые серверные контракты не назначены. Аналитика production пока недоступна,
поэтому ссылки на аналитические выборки там недоступны с объяснением; реальные
материалы/доступ/переименование работают независимо. Функциональность переходов
на наполненных данных проверяется только в явно изолированном fixture.
Независимого ревью, Firefox/Safari, TLS, полного backend suite/restart и CI этой
итерации нет; эти ограничения не заменяются статическими проверками.
