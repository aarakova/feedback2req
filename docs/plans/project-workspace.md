# Единая рабочая область проекта

Основание: запрос пользователя о двухуровневом UI и подтверждение зависимой
ветки от 9084a58. Существующий изолированный worktree, новая ветка
feat/project-workspace; исходная ветка доступа остаётся на 9084a58.

Проверено перед работой: origin/main=6c01d81, доступ 9084a58 ещё не интегрирован;
GitHub-поиск связанного PR не вернул результатов. Сначала интегрируется доступ,
затем эта зависимая работа. Merge/commit/push в текущем задании не разрешены.

Объём: общий тёмный layout observer, отдельная навигация всех проектов и
выбранного проекта, реальный обзор без вымышленных метрик, шесть разделов.
Материалы и доступ подключаются готовыми компонентами без переписывания
операций. Находки/требования/обработка — только честные информационные экраны.
Переименование через существующий PATCH предлагается отдельной итерацией.

План:
1. Выделить общий layout, проектную оболочку, навигацию/header и hash-разбор.
2. Добавить обзор с реальными полномочиями/возможностями и будущие разделы.
3. Сохранить материалы/access и ограничения времени жизни запросов/черновиков.
4. Добавить браузерные сценарии маршрутов, контекста, отсутствия демо и a11y.
5. Build и полный Playwright на настоящих API/PostgreSQL через Vite и Nginx;
   отдельные собственные Docker-ресурсы без изменения общих tags/контейнеров.
6. Зафиксировать результаты и предложить независимые следующие итерации.

## Будущие итерации — предложения, не утверждённые HTTP-контракты

| Итерация | Цель и зависимости | Сценарии/состояния | Приёмка |
|---|---|---|---|
| Переименование | Owner меняет name через существующий PATCH проекта | Ввод, сохранение, валидация, потерянный ответ и сверка через GET | Только Owner, реальное имя после reload, отсутствие ложного успеха |
| Находки | Нужен отдельно утверждённый backend чтения находок/групп и их доступных оснований, пагинации и охвата | Список, детали, переход к источнику, загрузка/ошибка/подтверждённая пустота/утрата основания | Реальные результаты одного проекта, сохранение отдельных конфликтующих позиций и происхождения |
| Требования | Нужен отдельно утверждённый backend чтения требований/редакций, оснований и проверок; изменения и человеческие решения — следующими подэтапами | Список/детали, человеческое решение отдельно от проверки и доступности оснований, ограниченный охват/ошибки | Нет вымышленного Approved; точные редакции/основания, права сервера |
| Обработка | Требуются утверждение спецификации worker и backend запуска/чтения запусков, ошибок и допустимых повторов | Явный запуск, фактическое состояние, ошибка/частичный результат/неизвестный исход запуска | Никакого фиктивного прогресса, корректные повторы и изоляция проекта |

Названия будущих HTTP endpoints/схем здесь не назначаются. Чтение разделов и
изменяющие операции могут вводиться отдельными небольшими итерациями.

## Результаты

Выделены Layout (общий shell/sidebar), ProjectLayout (проверка проекта и
подключение разделов), ProjectNavigation/ProjectHeader, ProjectOverview и
чистый hash-разбор routes. Projects сохраняет только список/создание проектов.
Материалы/доступ, ApiClient/ui и все 40 прежних тестов не изменены.
Сохраняются root проекта, materials с выбранным источником/документом и access;
новые клиентские разделы findings/requirements/processing информационные.
Некорректный маршрут показывает отдельную 404-страницу без данных проекта.

Обзор не делает запросов списков для счётчиков; отображаются поддерживаемые
возможности, реальные полномочия и ссылки на действия. Проектная навигация
включает шесть разделов для Owner и пять для Member/Approver. Роли менять
в UI нельзя. При проверке проекта его chrome скрывается, а формы той же
сессии/проекта сохраняются; прежние ключи и AbortController защищают контекст.

Фактически выполнено:
- TypeScript/Vite build — PASS.
- Отдельный production Docker build с уникальным тегом — PASS.
- Playwright/Chromium через Vite → настоящий API/PostgreSQL: **48 passed**,
  включая 8 новых сценариев и все 40 прежних регрессий.

- Готовая production-сборка: Playwright/Chromium через Nginx → настоящий
  API/PostgreSQL: **48 passed**, те же 40 регрессий и 8 новых сценариев.
- Проверены screenshot desktop 1280×720 и mobile 390×844/320×844,
  клавиатура, видимый focus, skip-link, единственный aria-current.
  Горизонтального переполнения нет. git diff --check — PASS.

Оба полных browser-прогона прошли с первого запуска, тесты/ожидания прежних
сценариев не ослаблялись. Изолированная БД feedback2req_layout_test и ресурсы
f2r-layout-adf660ee не используют рабочие данные/порты. Production-путь

## Интеграция и оставшиеся ограничения

Все части текущего frontend-этапа реализованы. Находки, требования и обработка
остаются неподключёнными; новый layout не означает готовности этих подсистем.
Счётчики и аналитика не выводятся без реального полного/агрегированного API.
Переименование и будущие API требуют отдельных согласований по таблице выше.
