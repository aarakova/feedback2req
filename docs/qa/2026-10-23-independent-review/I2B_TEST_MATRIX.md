## Общие предусловия и данные

После отдельного утверждения спецификации и разрешения реализации:

- F0: отдельная PostgreSQL 17, новая/заполненная m02a; только синтетические данные.
- F1: проекты P/Q, Owner O, Member M, Approver A, outsider X; независимые сессии.
- F2: в P по два source/document с различными текущими state; прежние состояния
  готовятся тестом SQL после утверждения схемы. Q имеет собственные материалы.
- F3: точные тексты `ё🙂\r\n` (4 code points / 8 UTF-8 bytes), комбинируемые
  знаки, табуляция, LF/CRLF, символы вне BMP; независимый Python-оракул подсчёта.
- F4: изолированный worker/init/probe и отдельные управляемые соединения/процессы.
  Никаких перезапусков общего Docker Engine или пользовательской БД.

В каждой строке применимы F0–F4 по необходимости; конкретные дополнения указаны
в колонке входных условий. «PG: да» означает настоящую PostgreSQL, не SQLite.
Модульные часы допустимы только для чистых правил; они не заменяют транзакции.

## Приёмка результатов будущих тестов

Сохранять версии Python/PostgreSQL/Engine/Compose/ядра/init, image IDs, Docker
events, ограничения ожиданий и снимки соответствующих строк БД. Новый ID
контейнера не обязателен: важны RestartCount, StartedAt и новая идентичность
процесса. Один unhealthy или ненулевой код probe не доказывает restart.

После каждого fault проверять сохранность независимых результатов, отсутствие
двойной публикации, отсутствие автоматического business retry и утечек. Одно
исключение commit() без подтверждения реального серверного исхода недостаточно.
Все 44 строки сейчас имеют статус **NOT IMPLEMENTED / NOT RUN — PROVISIONAL**.
