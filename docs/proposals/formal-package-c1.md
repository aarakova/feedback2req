# C1: доверенный снимок, review предпосылок и условный формальный результат

**PROPOSED, редакция 0.1, 2026-11-21. Не разрешение реализации.**
Уточняет [пакет C](workflow-contracts.md#c-доверенный-обмен-и-формальная-проверка)
и [обмен F2](qwen-z3-f2-exchange.md), не утверждает HTTP/SQL/хранение.
Проверенная исходная интеграционная база — `6000656`. Действуют AI 1.0,
DOMAIN/FR-023–FR-026 и INT-2026-11-06. Backend/worker/frontend не меняются.

## Предлагаемый приёмочный срез

Один добровольный отдельный сеанс проверки двух атомарных ожиданий об одном
параметре, выбранных человеком из exact Findings либо полных позиций группы.
Пара допустима и без обнаруженного AI-конфликта. Группа не считается истинным
конфликтом, совпадение слов — подтверждённым сопоставлением.
Сначала read-only snapshot/review/result без постоянного хранения; product
endpoint или способ вызова требует отдельного решения. Эта итерация реализует
только автономную механическую сверку DTO и тесты, не этот сеанс в приложении.

| Шаг | Доверенный вход и действие | Условие перехода / отказ |
|---|---|---|
| 1. Получение снимка | Приложение проверяет проект/Member, явно выбранные exact refs, доступность источников; фиксирует состав/состояния в одной согласованной короткой транзакции | Недоступно/изменилось → snapshot_unavailable/stale, без подстановки текущего |
| 2. Происхождение | Exact run/unit/accepted attempt; полный исходный canonical request/accepted response, local→persistent mapping с group/state/conflict/position и source provenance | Нет любого поля → snapshot_incomplete; не восстановление по GroupDetail |
| 3. Подготовка | Человек либо AI предлагает атомы e=(o,p,C,A,s), пропуски, разложение и выбранную пару; подготовка структуры существующим bridge | Неверный тип/размерность/зависимость A(C)/изменение известных полей → диагностика; никакого достраивания |
| 4. Review | Независимый уполномоченный человек проверяет поля против конкретных точных оснований, сопоставимость, атомаризацию/контексты и Ω | Pending/rejected/uncertain не дают trusted receipt; AI не может подтвердить себя |
| 5. Z3 | Существующий checker с ограниченным числом вариантов/solver calls/time/memory, вне транзакции | D/K/S либо U только при завершённой проверке допустимого полного Ω; технические отказы отдельно |
| 6. Представление | Повторная проверка доступа/доступности/selected states; условный read-only результат с версиями и границами | Изменение снимка аннулирует применимость review; новый снимок/версия и новый review, без правки истории |

Чтение нескольких GET страниц не является единым снимком. Строки JSON, hashes
и клиентские true-флаги не удостоверяют права/происхождение. Нельзя повторно
читать текущую группу вместо выбранной historical group/state. Последняя
доступная цитата не заменяет полный недоступный source state.

## Что уже есть и чего не хватает

| Интеграция предоставляет | Следствие для C1 |
|---|---|
| GET exact GroupDetail; members.ref/Finding; conflicts.positions.findings | Можно механически сверить exact refs и полный состав. Positions не сокращаются до одного представителя |
| F1 immutable Finding/Fragment, source_ref/text_ref/quote/locator/reliability | Можно проверить принадлежность и срез **предоставленного точного** source text. Reliability не повышается, inferred не становится direct |
| Unit.input и Attempt.grouping_result.input_findings | Есть input key↔Finding state, но нет полного исторического запроса/ответа/local output mapping |
| Group coverage/annotations/freshness, provider/model/synthetic/ai_performed | Сохранять отдельные значения. Completed/AI-conflict/current не доказывают смысл или полноту |
| GET текущего Source | Не обещает общий исторический source text; отсутствие selected state не обходится цитатой/текущим текстом |
| build_request внутри F2/F3 | Строит текущий проверенный вход, а не доказанную копию старого canonical вызова; после изменений может законно отказать |
| Нет approved canonical archive/output mapping/review persistence | Нельзя реализовать exporter «восстановлением». Нужен отдельно согласованный источник точных данных или явный отказ для старых попыток |

Результаты группировки и annotations могут быть проекцией нескольких групп.
Один GroupDetail не содержит все группы/ungrouped и тела considered non-members;
не хватает исходных DocumentExcerpt/previous_groups контекстов, request identity
и полного mapping. Возможность восстановить похожий запрос не доказывает
тождество исходному. Для старых попыток без точных данных предлагается отказ
snapshot_incomplete, а не ретроспективное утверждение восстановленного пакета.

## Проверяемое соответствие формализации

Для каждого атома review должен включать finding state, fragment state,
source/text state, locator и отдельные объяснения для object/parameter/C/A.
Каждое известное поле: прямое основание либо явно отмеченная интерпретация;
отсутствие сведений — null/missing_fields. Отдельно проверяются алиасы параметров,
размерности/единицы, пересечения контекстов и разложение многосоставной находки.
Все findings позиции учтены источниками атомов или явными мотивированными
omissions; omission не доказывает нерелевантность без review. Несколько атомов
одной находки не считаются независимыми людьми/подтверждениями.

Предлагаемые review-поля: snapshot/proposal/model/packet hashes и версии,
reviewer identity/authority, независимость от AI-предложения, время,
field-level verdict/rationale, пять подтверждений существующего bridge.
Receipt создаёт доверенный код только после принятия всех применимых критериев
того же снимка. Переданный AI review file или объявление reviewer_kind=human
не удостоверяют автора. Пользовательские причины — данные, не исполняемый код.

## Полнота Ω относительно выбранной модели

Пакет полноты должен явно указать модель/версию, границы рассматриваемых
неизвестных, способ получения вариантов, источник каждой альтернативы,
неизменяемые известные части и обоснование покрытия. Допускаются:

- полная заданная пара: единственное уточнение;
- явный конечный набор допустимых альтернатив выбранной предметной модели,
  полный перебор которых подтверждён независимым экспертом.

Неограниченное пространство реального мира, произвольные числовые уточнения,
неподтверждённые условия и просто конечный ответ AI не дают гарантии полноты.
AI может предложить кандидатов, но не omega_complete_confirmed. Эксперт не
должен механически принимать declared_complete=true; при недостаточном основании
вердикт uncertain и formal class отсутствует. Известные части не меняются при
уточнении. Ω пусто — ошибка формализации; разные D/K/S в полном Ω — U;
один класс в полном Ω — этот класс; одинаковый класс только в исследованной
части не доказывает однозначности. Ресурсное прерывание — технический отказ.

## Представление результата, отдельное от HumanDecision

Предлагаемые read-only поля результата, **не HTTP DTO**:

```text
snapshot/proposal/review/model versions+hashes; exact finding/group/source refs;
selection+omissions; reviewed assumptions; omega method/source/declared completeness;
trusted completeness rationale; explored variants and limits;
execution status; classification D/K/S/U | null; typed diagnostics;
solver/native version, seed, limits; interpretation limits; availability/freshness;
human_decision: separate, unchanged
```

Показывать C/A, предпосылки, основания и причины воздержания, не только букву.
U обозначает разные исходы допустимых уточнений; no-review/snapshot_incomplete/
unsupported/invalid/unknown/timeout/resource_limit/internal_failure имеют
собственные состояния без класса. Audit matched не заменяет review.

C1 не входит в обязательную цепочку Run/Unit/Attempt generation/verification,
не продлевает её lease, не меняет completed и не создаёт requirement-blockers
из технического отказа Z3. Основной цикл требований завершается независимо.
Z3 не назначает Approved/Rejected, не разрешает старые блокеры и не отменяет
предыдущее HumanDecision. Существующие доменные правила человеческого решения
и блокеров сохраняются; этот документ не добавляет новый обязательный gate.

Хранение/журналы не должны создавать обход удаления источников. В предлагаемом
первом сеансе не сохранять новый архив сырого текста; повторное чтение и
проверка прав обязательны. Постоянное хранение formalization/review/result,
удаление, права и retention требуют отдельного SQL/DTO предложения и approval.
[Прежнее предложение хранения](formal-expectations-results.md) остаётся PROPOSED.

## Решение, которое требуется для реализации C1

1. Утвердить источник точного snapshot и mapping: предлагается серверный
   односеансовый read-only exporter после проверки доступа, без восстановления
   отсутствующих historical canonical данных. До определения способа сохранения
   исходных mapping применять только к доступным точным пакетам; старым — отказ.
2. Утвердить отдельно от права Approver полномочие reviewer предпосылок и
   способ удостоверения review; предлагается текущий ProjectMember как reviewer
   при явной человеческой проверке, AI исключён. Это предложение, не действующая роль.
3. Утвердить временный независимый сеанс без product persistence и без зависимости
   основного цикла; конкретный способ вызова/DTO и обработку изменений доступа.

Приёмка после approval: concurrent state/access changes; exact исторические refs;
полные позиции и omitted sources; unknown без универсального дополнения;
неполное/пустое/подложно полное Ω; snapshot-bound review replay rejection;
D/K/S/U и технические отказы; завершённый основной Run не изменяется; отсутствие
HumanDecision side effects и обхода удаления. Текущая автономная проверка
подготавливает эти сценарии, но не утверждает и не реализует product C1.
