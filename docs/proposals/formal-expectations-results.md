# Прикладной результат формальной проверки пары ожиданий

**Статус: PROPOSED. Редакция 0.1, 2026-11-06.**

Отдельное предложение для последующего согласования. Не утверждает новый
AI JSON Schema, HTTP/DTO, таблицу PostgreSQL, миграцию или изменение worker.
Не вводит четвёртую продуктовую AI-роль. Локальный автономный адаптер описан в
[README](../../ai/formal_expectations_bridge/README.md); его dataclass не
является утверждённой прикладной моделью хранения.

## Проблема и точка будущего вызова

Конфликт group_findings 1.0 хранит описание и отдельные позиции со ссылками
на находки. Он не содержит формализацию `(o,p,C,A,s)`, атомарное разбиение
контекстов, Ω или машинную диагностику решателя. Добавление этих полей в закрытую
схему 1.0 несовместимо с действующим контрактом.

Предлагается отдельный прикладной результат, связывающий **одну явно выбранную
пару атомов** с точными состояниями Finding. Группы/позиции — контекст выбора,
а не самостоятельное основание. После получения принятого снимка группировки
прикладной слой разрешает подготовку/проверку атомов и вызывает Z3 вне
транзакции. Перед публикацией заново проверяет права, доступность оснований,
состояния и владение соответствующей попыткой, если выполнение будет связано
с ProcessingRun. Конкретный lifecycle и связь с Run требуют отдельного решения.

## Предлагаемое содержание FormalPairCheckResult

| Раздел | Поля/смысл |
|---|---|
| Идентичность | Версия этого формата; ID результата, project_id и точная область двух атомов; постоянные ID назначает приложение |
| Подготовка | ID/версия формализации, origin human/ai с проверяемым авторством/методом; полный выбор позиций/находок; разложение, явно исключённые находки, невыбранные атомы и объяснения |
| Модель | ID и версия модели; сопоставленные object/parameter; тип/размерность/единицы; домены; атомарные ситуации и отображение исходных контекстов с отношениями пересечения |
| Основание | Для каждого атома точные Finding StateRef и выбранные Fragment/source/text StateRef, locator/time/reliability в пределах разрешённых данных; доступность основания отдельно от исторической связи |
| Вход solver | Полный структурированный вход выбранной пары либо ссылка на разрешённый доступный снимок; явные null и причины недостающей информации; никакого исполнения пользовательских формул |
| Ω | Все фактически рассматриваемые варианты; источник/метод/обоснование; отдельно declared_complete, trusted confirmation и граница модели; число рассмотренных вариантов |
| Доверенная проверка | ID/версия verifier, проверяемый момент/контекст и ссылка на подтверждения основания, формализации, сопоставимости, разбиения и полноты Ω; связь с точным входом |
| Выполнение | Версии bridge/формального компонента/native Z3/z3-solver; seed/параметры, временные и ресурсные бюджеты, фактический исход отдельных запросов |
| Формальный итог | D/K/S/U только после всех допустимых успешных проверок; complete, observed_classes и объём; при отказе classification=null, отдельные код/причина/этап диагностики |
| Интерпретация | Всегда явно: класс относительно принятой модели, не утверждение реального смысла; только пара, не глобальная совместимость, не автоматическое устранение конфликтов |
| Экспертная оценка | Отдельная запись автора/версии/метода/обоснования и состояния pending/accepted/rejected/uncertain; не вычисляется из sat/unsat и не переписывает историю запуска |

Допустимые значения состояний выше — **предложение**, не новые утверждённые
предметные статусы. Доверенная проверка не равна человеческому решению по
требованию. Экспертная оценка формализации и HumanDecision остаются разными.

Класс и диагностика взаимоисключаются в окончательном исходе выполнения.
`solver_unknown`, timeout, ресурсы, невалидный ввод и неполное Ω не имеют класса U.
Частично наблюдённые классы могут быть диагностическими фактами, но не итогом.
Пустое Ω — ошибка формализации. Полнота реального мира не гарантируется.

## Привязка к группе и состояниям

Для принятой backend-группы нужны её постоянные group/state IDs и точные позиции
этого состояния. В автономном ответе AI local_id не является постоянным ID;
приём должен явно сохранить/проверить отображение local → persistent.
Две позиции могут иметь несколько подтверждающих находок; нельзя молча выбирать
первую. Несколько атомов из одной находки не становятся независимыми отзывами.

Повторные проверки получают отдельные результаты. Старый точный state не
заменяется текущим, ID текста/его hash не подменяют идентичность источника.
Изменение модели, атомов, Ω или состояния основания требует новой проверки;
старый результат остаётся историческим в пределах разрешённой политики удаления.

## Доступ и удаление

Предлагается наследовать проектную изоляцию и права доступа к основаниям.
Снимок не должен обходить утверждённое удаление FeedbackSource/Transcript/Fragment.
Нельзя постоянно архивировать исходный текст, координаты/время/ID фрагментов
или hash удалённого содержимого под видом formal_input или квитанции.

Нужен отдельно согласованный механизм очистки/инвалидации: при удалении
источника очищать запрещённые сведения и digest содержащего их снимка,
закрывать доступ к нему и маркировать утрату основания результата. Исторический
формальный исход не выдаётся за доступное текущее подтверждение. Сохраняться
могут только разрешённые производные сведения; конкретный состав и FK/storage
не утверждаются этим предложением. Удаление проекта охватывает результаты
проверок и их происхождение в приложении.

Локальный packet_sha256 адаптера — эфемерная привязка точного синтетического
входа, **не** согласованное долговременное хранилище удаляемых текстов.

## Требуемые решения перед реализацией хранения

1. Согласовать состав постоянного результата и политику очищаемых снимков,
   отдельно от закрытых AI JSON Schema 1.0.
2. Назначить источник доверенных проверок/смыслового review и процедуру
   подтверждения Ω относительно ограниченной модели; одно заявление AI недостаточно.
3. Согласовать lifecycle публикации, повторных проверок/устаревания/отмены
   и связь с точными состояниями F2, без автоматического изменения HumanDecision.
4. После согласования отдельно проектировать физическую БД/DTO/API/worker,
   миграции, concurrency/permissions/deletion tests. Сейчас они не реализуются.
